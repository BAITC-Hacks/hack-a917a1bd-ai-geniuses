# Проверка прототипа OrgLens

Дата: 23 сентября 2026 года. Среда проверки: Windows, Python 3.12.14, Node.js 24.19.0, npm 11.17.0. Python-пакеты закреплены в `backend/requirements.txt`, Node-пакеты — в `frontend/package-lock.json`.

## Обновление интерфейса

### Интерактивный запуск на одном адресе

Добавлен `npm run build:portable`: проверка TypeScript и настоящая сборка Vite/Rollup (29 модулей) успешно проходят в текущем процессе Node.js без сервиса esbuild и без повышения разрешений. Это заменяет ранее заблокированную сборку для локального запуска. Backend раздаёт только `frontend/dist`, API сохраняет свои маршруты. Приложение доступно на `http://127.0.0.1:8000/`; на Windows добавлен `start-orglens.cmd`.

Три новых теста `test_frontend_serving.py` пройдены: HTML/CSS и API доступны, файлы вне dist и попытки обхода пути не выдаются, API работает без сборки. В браузере проверено именно собранное приложение: выбор DOCX через кнопку, удаление выбранного файла, открытие сохранённого анализа через форму, переключение раздела «Функции», раскрытие оснований и получение точной цитаты через API. Новые запросы к OpenAI при этих проверках не выполнялись.

Переработаны экран загрузки, навигация, обзор результатов, карточки функций, риски и панель источников. Длинные основания и ограничения раскрываются по запросу. Счётчик найденных соответствий больше не учитывает функции со статусами `uncertain` и `not_found`; при переходе назад сбрасываются фильтры предыдущего анализа.

Для этой версии `npm run typecheck` проходит. Повторная производственная сборка `npm run build` заблокирована ограничением запуска дочернего процесса esbuild (`spawn EPERM`). Успешная сборка в таблице ниже относится к первоначальной версии, до переработки дизайна.

В уже работающем приложении проверены выбор и удаление учебных DOCX/XLSX, доступность кнопки сравнения только после заполнения обоих комплектов, открытие сохранённого частичного анализа с заполненными результатами, карточки функций и исходная цитата DOCX. Закрытие панели через Esc возвращает фокус на ссылку источника. Новые запросы к OpenAI для проверки дизайна не выполнялись; содержимое сохранённых результатов не изменялось.

После этих проверок dev-сервер перестал отвечать. Итоговый CSS проверен через статическую разметку, полученную из того же `App.tsx` средствами ReactDOMServer: экран загрузки, обзор и риски на обычной ширине; загрузка и карточки функций при viewport 390 × 844. Горизонтального переполнения страницы нет (измерены clientWidth/scrollWidth). Для заполненных статических экранов использован ранее сохранённый результат учебного анализа. Это проверка оформления, а не новый прогон API или интерактивных сценариев. Временный renderer и тестовые страницы не входят в исходники приложения. CSS успешно разбирается PostCSS; финальная проверка TypeScript проходит. Для просмотра полного приложения требуется запустить frontend обычной командой из README.

## Выполненные проверки

| Команда / сценарий | Результат |
|---|---|
| `python -m pytest -q` из `backend` | 81 тест пройден |
| `npm run typecheck` из `frontend` | Успешно, ошибок TypeScript нет |
| `npm run build` из `frontend` | Успешно, Vite 7.3.6, 29 модулей |
| `python -m pip check` | Несовместимых установленных зависимостей не найдено |
| `python -m compileall -q backend/app scripts` | Успешно |
| `python scripts/live_evaluation.py` — первичная проверка | Ключ отсутствовал; скрипт сообщил это и завершился без успеха |
| `python scripts/live_evaluation.py --max-calls 40` — после настройки ключа | Выполнены 3 попытки обращения к API; ответ не получен из-за ошибки сети/соединения. Анализ завершился со статусом `failed`, качество реальной модели не проверено |

Для Python использовалось созданное локальное окружение `.venv/Scripts/python.exe`. Из-за ограничений песочницы доступ pytest к Windows Temp и запуск esbuild требовали разрешённого запуска команд. Первые неуспешные прогоны не считаются успешными проверками; приведены результаты после исправлений.

Тесты включают парсинг и адреса DOCX/PDF/XLSX, сканы и смешанные PDF, таблицы/колонки, формулы, лимиты, повреждённые файлы, файлы с внутренним UUID без расширения, цитаты и принадлежность источников, передачу и частичное покрытие, разные роли, дублирование, независимый аудит, неполноту, отмену функций и сохранение старых положений, отрицательные приказы, бюджет/кэш/ошибки API, изоляцию анализов, восстановление после перезапуска, экранирование и заполненный HTML-отчёт.

Семь тестов используют настоящий установленный OpenAI SDK с локальным mock HTTP transport: проверяются строгие вложенные схемы Structured Outputs и разбор Responses API без обращения к сети. Остальные аналитические сценарии используют отдельный `FakeLLMProvider` только из тестов. **Эти тесты не доказывают качество ответов реальной модели.**

## Проверка в браузере

Проверен настоящий локальный интерфейс, подключённый к FastAPI:

- Выбор DOCX ДО и нескольких документов ПОСЛЕ, показ размеров и количества файлов.
- Запуск анализа и получение реального статуса через polling.
- Понятная ошибка отсутствия `OPENAI_API_KEY`, без подстановки выводов.
- После исправления чтения XLSX полный демокомплект: **6 из 6 документов прочитаны, 64 фрагмента**, вызовов OpenAI — **0**.
- Панель DOCX: пункт 1.3, абзац 7 и контекст Центра ИТ.
- Панель XLSX: лист «Функции ПОСЛЕ», ячейка C4, контекст строки «Отдел инфраструктуры».
- Панель PDF: реальная страница 1, пункт 1.2, ссылка на оригинал с `#page=1`.
- Вкладка заключения: состояние отсутствующего AI-заключения, полнота, ограничения и доступные ссылки экспорта.
- Обновление страницы сохраняет `analysis_id` и открывает сохранённое состояние без нового анализа.
- При проверке консоли ошибок и предупреждений приложения не обнаружено.

Заполненные матрица, риски и аналитическое заключение проверены на уровне backend и HTML-рендера с тестовым провайдером. Их качество на ответах реального OpenAI и полный браузерный сценарий с настоящим AI-результатом **не проверены**.

PDF и XLSX демокомплекта отрендерены и просмотрены. DOCX открываются парсером и проходят структурные тесты; визуальный рендер DOCX недоступен в этой среде, потому что LibreOffice отсутствует. Команды Linux/macOS приведены в README, но здесь не запускались.

## Исправления, найденные проверками

- Синхронизировано одновременное чтение/атомарная запись JSON на Windows.
- XLSX читается из бинарного потока: имя хранения без расширения больше не отвергается библиотекой.
- Отрицания, отмена решения и посторонний приказ не принимаются за прямое подтверждение изменения.
- Ограничения AI-извлечения снижают полноту и запрещают уверенный вывод о потере.
- Нормализованные поля функций проходят отдельную смысловую проверку по исходникам.
- Цитата из точки или произвольного короткого подфрагмента не подтверждает всю функцию.

После первичной проверки пользователь предоставил ключ. Он сохранён только в `backend/.env`, который исключён из Git и архива исходников; backend перезапущен и подтвердил наличие конфигурации. Значение ключа не включено в этот отчёт.

Повторная живая оценка использовала только синтетический комплект. Ответ OpenAI получить не удалось: после трёх попыток зафиксирована ошибка сети или превышение времени ожидания, сущности и выводы не сформированы. Попытка запуска вне песочницы автоматически отклонена действующей политикой разрешений. Эта ошибка не устанавливает ни корректность ключа, ни доступность модели в аккаунте. Для независимой проверки можно выполнить команду live evaluation в обычном локальном терминале из папки проекта.

Публикация и git push не выполнялись. Пользовательские корпоративные документы в живой проверке не использовались.
